# 使用说明

本文按当前已完成代码整理。项目概览见 [README.zh-CN.md](../README.zh-CN.md)。

## 1. 安装与启动

### Windows

```powershell
irm https://raw.githubusercontent.com/guangcheng9/Veil/master/scripts/install.ps1 | iex
```

脚本会安装 `veil.exe`、加入用户 PATH 并启动 Veil。重新打开终端后运行：

```powershell
veil setup
```

也可以从 Releases 下载 `veil-windows-x64.exe` 后直接双击。

### Linux / macOS

从 Releases 下载对应平台二进制，添加执行权限后运行：

```bash
chmod +x veil-linux-x64
./veil-linux-x64
```

Release 同时提供 `SHA256SUMS`，建议先校验。

默认监听：

- 数据面/代理：`127.0.0.1:18787`
- 管理页：`127.0.0.1:18788`

管理页地址可随时通过 `veil ui` 获取。该命令会输出并打开带管理令牌的地址。

## 2. 接入支持的软件

运行：

```powershell
veil setup
```

按编号选择软件。Veil 会尝试读取该软件当前的 API 地址，为它分配独立本机端口，再把该软件指向 Veil。

当前支持：

- Claude Code
- Codex
- PI Agent
- CodeBuddy
- Grok Builder
- Hermes
- Trae

也可以直接指定：

```powershell
veil setup --clients claude,codex
veil setup --clients all
veil setup --clients claude --upstream https://relay.example.com
```

行为说明：

- 每个软件使用独立端口，当前从 `18791` 起分配。
- 新增专用端口后，需要同时重启 Veil 和目标软件。
- 若端口已存在，只修改上游后重启转发即可。
- 读取不到软件原地址时，Veil 会使用已有路由、`--upstream` 参数或通用上游。已有客户端地址或已有路由优先于 `--upstream`。

## 3. 手动接入其他工具

工具必须支持修改 Base URL，并且使用 Veil 支持的协议。

| 协议 | Base URL |
|---|---|
| Anthropic Messages | `http://127.0.0.1:18787` |
| OpenAI Chat Completions / Responses | `http://127.0.0.1:18787/v1` |

支持的请求路径：

- `/v1/messages`
- `/v1/messages/count_tokens`
- `/v1/chat/completions`
- `/v1/responses`
- `/v1/models`
- `/v1/embeddings`

通用端口 `18787` 对未识别路径返回 `404`。按软件创建的 Anthropic/OpenAI 专用端口会把其他路径归入该端口对应的协议族。

### Claude Code

```powershell
$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:18787"
claude
```

官方订阅登录不需要额外填写模型 API Key。使用自定义中转时，Key 填中转提供的那一把。

### Cursor

Settings → Models → OpenAI Base URL：

```text
http://127.0.0.1:18787/v1
```

API Key 填实际上游的 Key。

### Codex / 其他 OpenAI CLI

```powershell
$env:OPENAI_BASE_URL = "http://127.0.0.1:18787/v1"
$env:OPENAI_API_KEY = "<上游 Key>"
```

也可以让 `veil setup --clients codex` 修改已有 Codex 配置。

### Python / Node OpenAI SDK

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:18787/v1",
    api_key="<上游 Key>",
)
```

```js
const openai = new OpenAI({
  baseURL: "http://127.0.0.1:18787/v1",
  apiKey: "<上游 Key>",
});
```

### 公司中转 / LiteLLM / New API

1. 在管理页「上游」填写中转根地址。
2. 工具 Base URL 指向本机 `18787` 或 `18787/v1`。
3. 工具中的 Key 使用中转提供的 Key。

上游根地址可以填写官方地址或中转地址。Veil 会去掉末尾 `/v1`，再根据请求路径拼接，避免重复 `/v1`。上游修改后需要重启转发。

## 4. 规则

管理页「规则」中可以看到内置规则、自定义规则和白名单。

内置规则类型：

| 类型 | 内容 |
|---|---|
| `PEM` | 私钥块 |
| `APIKEY` | 常见 API Key 格式和键值赋值 |
| `TOKEN` | Bearer、JWT、常见 Token 前缀和赋值 |
| `CONNSTR` | 数据库/中间件连接串及常见连接参数 |
| `PASSWORD` | 常见密码赋值 |
| `PHONE` | 中国内地手机号 |
| `IDCARD` | 身份证号 |
| `IP` | 所有可解析 IPv4/IPv6，默认放行回环地址 |
| `EMAIL` | 邮箱，默认关闭 |

规则操作：

- 可以开关内置规则。
- 可以展开修改自定义规则的正则、词表、优先级和说明。
- 可以导入/导出自定义规则。
- 可以恢复内置默认规则。
- 白名单按完整字符串精确匹配。

规则、白名单和上游设置当前都需要重启转发后生效。看板的重启按钮会在存在未应用配置时显示提示。

映射按 **Creator + 明文** 保存。Creator 来自 `x-api-key`、`Authorization` 或 `api-key`；这些请求头仍会原样转发给上游。同一 Creator 下，相同明文复用同一占位符；换 Key 或 OAuth Token 刷新后不会自动复用旧映射。

## 5. 安全边界

Veil 处理：

- 请求体中的 JSON 字符串值。
- 非 JSON 文本请求体。
- 响应体中的 JSON 字符串值。
- SSE 文本 payload。

Veil 不处理：

- 请求头、响应头、Query、Path、HTTP 方法和 JSON key 的脱敏。
- Base64、data URL、多模态二进制内容。
- `multipart/form-data`；该请求直接返回 `415`。
- 规则未覆盖的秘密格式。
- 二进制附件中的秘密。

必要传输头会被重写，例如 `Host`、`Accept-Encoding`、`Content-Length`、`Transfer-Encoding` 和逐跳头。

常见错误：

| 状态 | 含义 |
|---|---|
| `404` | 请求路径未被当前监听端口识别 |
| `413` | 请求体超过默认 32 MiB 限制或配置上限 |
| `415` | multipart 请求 |
| `502` | JSON 解析、脱敏、映射写入、上游连接或 JSON 响应还原失败 |

## 6. 管理页

当前页面：

- **看板**：服务控制、最近 512 条缓存事件指标、最近 20 分钟趋势、更新检查。
- **规则**：规则、白名单、导入、导出、恢复默认。
- **上游**：通用上游、按软件上游、HTTP/HTTPS 代理、请求体上限、优雅停止超时。
- **密钥**：主密钥轮换、映射清理入口、管理令牌重置。
- **流量**：最近请求的方法、路径、状态、流式标记、命中类型、首包耗时、错误类别和 Creator 短前缀。

看板与流量数据来自内存缓存，不是累计统计，也不保存请求正文或 Query。

## 7. 数据目录与隐私

默认数据目录：

- Windows：`%LOCALAPPDATA%\veil`
- macOS：`~/Library/Application Support/veil`
- Linux：`${XDG_DATA_HOME:-~/.local/share}/veil`

可用 `VEIL_DATA_DIR` 覆盖。

常见文件：

- `config.toml`
- `mappings.db`
- `master.key`
- `admin.token`
- 运行时元数据和可选调试日志

映射的敏感列使用 AES-256-GCM 加密，查询索引使用 HMAC-SHA256。占位符 ID、Creator 哈希等元数据不做整库加密。若 `mappings.db` 与 `master.key` 被一起复制，持有者可以解密映射。

Veil 没有自动遥测或崩溃上报。正常流量只访问配置的上游；安装、手动检查更新和下载更新会访问 GitHub。

## 8. CLI

```text
veil                         启动并打开管理页
veil start --foreground      前台运行
veil stop                    停止 Veil
veil status                  查看状态
veil setup                   交互式接入软件
veil setup --clients LIST    指定软件
veil setup --upstream URL    设置通用/兜底上游根地址
veil ui                      打开带令牌的管理页
veil update --check          检查更新
veil update                  下载并安装更新
veil help                    查看帮助
```

常用环境变量：

```text
VEIL_DATA_DIR
VEIL_MASTER_KEY
VEIL_BIND
VEIL_MODE=desktop|server
VEIL_UPSTREAM_PROXY
VEIL_DEBUG
VEIL_GITHUB_MIRROR
```

旧的 `DGW_*` 环境变量仍兼容。

## 9. 已知限制

- 仅支持 Anthropic Messages、OpenAI Chat Completions 和 OpenAI Responses 协议族。
- 不支持 multipart 和附件扫描。
- Base64、data URL、多模态二进制内容不扫描。
- Headers、Query、Path、JSON key 不脱敏。
- 规则、白名单和上游修改需要重启转发。
- 上游页的映射 TTL 字段当前只保存配置，尚未接入 SQLite 存储。
- 按 Creator 清除映射的接口当前尚未实际删除数据库记录。
- 主密钥轮换会替换 `master.key`，但运行中的映射存储不会热重载；重启 Veil 后才会按新密钥打开存储。
- 请求体上限修改需要重启转发后生效。
- 优雅停止超时在停止时读取当前配置。
